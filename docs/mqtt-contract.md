# MQTT 通信契约（v1）

Broker 在本地控制端运行。所有主题以 `air/v1/` 开头；`<id>` 为 MAC 派生的不可变设备 ID。

| 主题 | 方向 | QoS | retained | 用途 |
| --- | --- | ---: | ---: | --- |
| `air/v1/<id>/availability` | 设备 → 服务 | 1 | 是 | `online` / `offline` |
| `air/v1/<id>/state` | 设备 → 服务 | 1 | 是 | 模式、开关、ADC 判定、光耦最终状态 |
| `air/v1/<id>/heartbeat` | 设备 → 服务 | 0 | 否 | RSSI、IP、运行时间、Wi-Fi 状态 |
| `air/v1/<id>/telemetry` | 设备 → 服务 | 0 | 否 | 可选 ADC 帧与诊断流 |
| `air/v1/<id>/command` | 服务 → 设备 | 1 | 否 | 设备命令与调试流配置 |
| `air/v1/<id>/ack` | 设备 → 服务 | 1 | 否 | 命令执行确认或失败 |

## 状态载荷

```json
{
  "schema": 1,
  "device_id": "pur-e83dc1951534",
  "sequence": 42,
  "mode": "low",
  "powered": true,
  "adc_mv": [121, 35, 42, 39],
  "opto": { "power": false, "mode": false },
  "wifi": { "rssi_dbm": -58, "ip": "192.168.1.181" }
}
```

## 命令载荷

每条命令必须有 `request_id`，设备在 `ack` 回传同一 ID，保证控制端可去重和等待确认。

```json
{
  "request_id": "a9e2f8d1",
  "type": "debug.configure",
  "adc_stream_hz": 20,
  "opto_trace": true,
  "expires_in_s": 60
}
```

`adc_stream_hz` 支持 `0–120 Hz`；调试台提供 10、20、30、40、50、60、120 Hz 档位。`0` 关闭 ADC 调试流。每个遥测包包含单调递增的 `seq`，控制服务据此计算实收频率和序号缺口。120 Hz 仅用于单机、短时间压力测试，不作为家庭日常配置。

遥测和心跳采用 QoS 0，并由固件直接发送，不进入持久 outbox；它们是允许丢弃的实时数据。状态、availability、诊断和命令回执采用 QoS 1。这样高频 ADC 不会阻塞心跳或下行控制命令。每次新的调试流从 `seq=0` 开始，控制服务同时重置该设备的速率窗口和缺口计数。

设备即使未启用调试流，仍会在模式、开关、光耦最终状态变化时立即发布 `state`。

## 命令生命周期

控制服务为每台设备最多保留 3 条等待中的命令。命令状态依次为 `sending`、`pending`，收到相同 `request_id` 的 `ack` 后变为 `acknowledged` 或 `failed`；15 秒未收到回执则记为 `timeout`。失败与超时都会保留在最近 50 条历史中。

远程重启使用 `device.reboot`。设备必须先发送 QoS 1 回执，延迟约 1.5 秒后才重启，使控制端能确认重启请求确实到达。

## 在线判定

正常心跳周期为 2 秒。控制服务采用三态判断：3 秒内有新心跳为 `online`；3–5 秒为 `degraded`，仍计入在线总数；超过 5 秒判定 `offline`。收到 MQTT Last Will 后同样保留 5 秒抖动窗口，新心跳一到立即恢复在线。这样一次延迟不会让设备立即消失，同时真正断电会迅速显现。

## 30 台设备的容量边界

日常模式下，每台设备每 2 秒发送一个心跳和一个状态包，30 台约为 30 条消息/秒，局域网负荷很低。若 30 台全部开启 120 Hz，则会达到 3,600 条小消息/秒；按每条消息连同主题、MQTT/TCP/IP 与无线帧开销约 200–400 字节估算，实际空口负荷约 6–12 Mbit/s，并会受到 2.4 GHz 小包竞争、重传和路由器客户端调度影响。这种配置没有实际调试价值，也会降低控制命令的及时性。

生产建议：状态变化立即上报，保留 2 秒心跳；普通远程波形使用 10–20 Hz；60/120 Hz 只允许单台设备、短时间开启。服务端保留三条并发命令的限制是命令背压，不用于限制遥测；批量调试应在控制端额外限制同时打开高频流的设备数。
