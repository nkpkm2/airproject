# 光敏电阻 ADC 标定向导

第一阶段原始采样仍完整保留；第二阶段在同一份数据上增加自动分段、启动瞬态抑制、独立基线、鲁棒阈值和质量报告。分析不会发送光耦命令、更改净化器模式或写入 ESP32 配置。

## 操作步骤

1. 在“诊断工具中心 → 光传感器标定向导”中打开 USB 串口或 Wi-Fi 入口。
2. 安装好 PCB，开机并调至低速，点击“开始自动标定”；低速会自动采样约 3 秒。
3. 只按净化器实体模式键，按提示依次完成：`低 → 中 → 高 → 自动`；每次切档后软件自动采样约 3 秒。
4. 完成自动档后按电源键关机，等待四路暗态稳定。
5. 导出原始 CSV/JSON 和分析报告 JSON；报告审阅通过后才考虑后续“应用标定”。

不要求每档停留固定时长，也不需要网页确认切换。切换瞬间、灯响应延迟、按键误触和短暂波动都保留在原始数据中；分析层只增加阶段标签，不删除样本。

## 两条采样路径

| 路径 | 原始数据来源 | 典型记录速率 | 序号 / 固件运行时间 |
| --- | --- | ---: | --- |
| USB 串口 | `ADC_FRAME` 串口帧 | 约 50 Hz（5 ms ADC、20 ms 帧） | 当前串口协议未提供，导出字段保留为空 |
| Wi-Fi | MQTT `telemetry` 临时 ADC 流 | 10 / 20 / 30 / 40 / 50 / 60 / 120 Hz | 设备 `seq`、服务端接收时间和 `uptime_ms` 一并保留 |

Wi-Fi 采样只向所选设备发送临时 `debug.configure` 请求以开启 ADC 遥测流。每次临时租约为 120 秒，记录仍进行时每 90 秒自动续期；停止时立即关闭该临时流。这样即使浏览器意外关闭，额外遥测负载至多持续约两分钟。它不触碰净化器控制光耦或持久配置。

## 导出格式

CSV 一行代表一个收到的帧，字段为：

```text
session_id,device_id,transport,received_at_iso,received_at_ms,
firmware_uptime_ms,sequence,sequence_gap_before,sequence_gaps_total,
requested_rate_hz,received_rate_hz,adc_low_mv,adc_medium_mv,adc_high_mv,adc_auto_mv
```

JSON 使用 `air-light-calibration-sample-v1`，同时保留会话元数据：传输方式、计划顺序、是否需要人工标记、是否提前分段、设备 ID、请求频率、统计信息和完整样本数组。它适合后续审阅及严格的离线分析。

## 自动分析规则

分析器使用 `CalibrationAnalyzer.start()`、`ingest()`、`finish()` 和报告接口。它会：

- 检测四路共同启动漂移，并屏蔽周期性自动灯启动脉冲；
- 按 `低 → 中 → 高 → 自动 → 关机暗态` 顺序寻找稳定平台；向导会在每档至少采样约 3 秒后再提示下一步；
- 为 GPIO0/ADC4（低）、GPIO4/ADC1（中）、GPIO3/ADC2（高）、GPIO1/ADC3（自动）分别建立基线、亮态、噪声和滞回；
- 对变化幅度、分布重叠、重复一致性、顺序、时间间隔和丢帧进行质量判定；
- 质量门限采用“强效应”或“中等效应 + 极低重叠”的双通道规则，避免某一路亮态噪声较大就被僵硬判为失败；
- 只输出可审阅报告，不自动应用阈值。

## 判定算法（亮 / 灭）

实时判定不是拿四路共用一条电压线，而是每路使用自己的统计模型：

1. 先用该路的暗态中位数和亮态中位数确定方向与有效区间；
2. 暗态边缘至少留出 `max(3 × 暗态 MAD 换算噪声, 3% 亮灭跨度, 2 mV)` 的安全余量；
3. 进入“亮”使用开灯边界，保持“亮”使用更靠近暗态的关灯边界，形成滞回；
4. 若两次边界之间的样本落在不确定带，保留上一状态，不把单个抖动点当成模式变化；
5. 如果旧配置没有亮灭分布数据且关灯边界为负值，则临时把开灯边界作为安全清除边界，避免 0.01–0.20 V 的暗态噪声把灯锁在“亮”。下一次成功标定后会自动使用新的分布模型。

因此，阈值来自真实数据但不会僵硬地依赖某个绝对电压；每一路的工作点、漂移和噪声都独立处理。

## 按设备保存与实时判定

当报告四路质量均为“通过”时，向导会显示“保存本设备参数”。保存动作只把归一化后的 `air-light-device-calibration-v1` 配置写入本机控制服务，并以 MAC 派生的不可变 `pur-xxxxxxxxxxxx` ID 作为键；串口传来的冒号格式 MAC 会自动映射到同一个键，不会产生重复设备。不会写入固件，也不会把一台设备的阈值用于另一台设备。每台设备都有同一套算法结构和自己独立的基线、方向、开阈值、关阈值及滞回。

控制服务接口为 `GET/PUT /api/v1/devices/{device_id}/calibration`。串口和 Wi‑Fi 调试页加载当前设备配置后，会在四路 ADC 卡片中显示实时“亮”（红色）或“灭”（浅灰色）；尚未完成或质量未通过的设备显示“未标定”，不会伪装成已校准的灭灯状态。
