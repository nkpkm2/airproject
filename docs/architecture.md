# 家庭空气管理系统架构

## 目标

系统支持约 15 台 ESP32-C3 净化器控制板。设备使用 DHCP，不依赖固定局域网 IP；每台设备以不可变设备 ID 识别，并由本地控制端统一展示、控制和记录状态。

## 组件边界

```text
firmware/（ESP32-C3）
  ├─ 硬件层：ADC、光耦、LED
  ├─ 净化器状态层：关机 / 低 / 中 / 高 / 自动与确认
  ├─ 网络层：唯一的受控 Wi-Fi 连接调度器
  └─ 通信层：MQTT 状态、诊断、命令、确认

control-service/（电脑或 NAS）
  ├─ MQTT Broker
  ├─ 设备注册与在线判定
  ├─ 命令路由、回执和历史数据
  └─ HTTP/WebSocket API

console/（浏览器）
  ├─ 家庭总览
  ├─ 板卡串口调试
  └─ 板卡 Wi-Fi 调试
```

## 身份与 IP

`device_id` 由 ESP32 的 STA MAC 派生，例如 `pur-e83dc1951534`。别名、净化器编号、房间归属均可由控制端修改。IP 仅作为状态字段上报，不能用于识别设备。

电脑连 5 GHz、ESP32 连 2.4 GHz 时，只要两者处于同一 LAN/VLAN 且没有无线客户端隔离，就可以正常通信。频段不同不等于局域网不同。

## Wi-Fi 所有权规则

每块设备只有一个连接调度器可以调用 `WiFi.begin`、`WiFi.disconnect` 或开始扫描。当前固件使用真正的事件驱动状态机：

```text
Disabled → Scanning → Associating → DHCP → Online
              ↑             ↓                ↓
              └──── Backoff / Failed ────────┘
```

- 上电后从 NVS 读取已配置的网络并开始受控连接。
- 不使用 SDK 自动重连；重试只能由 `WifiManager` 执行，并采用退避时间。
- 联网扫描、漫游关联、BSSID 降级尝试与退避均在 `loop()` 中分步推进；ADC、串口和 MQTT 不会因某次关联而停止。
- 手动连接、重新配置和扫描均由同一调度器串行执行，不能并发操作射频。
- Wi-Fi 密码只保存到设备 NVS 或本地服务配置，绝不写入 Git 可提交源码。

## 流量分级

| 类别 | 默认 | 传输方式 |
| --- | --- | --- |
| 在线、离线、模式、开关、命令回执 | 开启 | MQTT QoS 1，状态 retained |
| RSSI、IP、运行时间 | 低频开启 | 1–3 秒心跳，QoS 0 |
| ADC 波形、光耦详细时序、诊断日志 | 关闭 | 仅调试启用，QoS 0，有超时 |

设备断电或链路失效由 MQTT Last Will 和心跳超时判定离线。调试流必须带 `expires_at`，到期自动关闭。
